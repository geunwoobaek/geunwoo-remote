# Happy 원격 사용성 개선 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 폰에서 Happy 세션을 쓸 때 작업 중 메시지가 바로 전달되고, 최신 모델로 돌고, 작업 진행·HTML·히스토리를 앱 안에서 볼 수 있게 한다.

**Architecture:** 1단계는 맥 CLI(`packages/happy-cli`)만 고쳐 스토어 앱에서도 효과가 난다. 2~5단계는 안드로이드 앱(`packages/happy-android`) 포크를 dev 빌드(`com.slopus.happy.dev`)로 설치해 쓴다. 3단계만 세션 프로토콜에 포크 전용 이벤트를 더한다.

**Tech Stack:** TypeScript + Vitest + Claude Agent SDK(CLI), Kotlin + Jetpack Compose + Gradle(안드로이드).

**Spec:** `docs/superpowers/specs/2026-11-08-remote-ux-design.md`

## Global Constraints

- Claude는 항상 이 맥에서 실행한다. Remote Control·클라우드 실행 금지. 세션 내용은 Happy 중계(종단 암호화) 외로 나가지 않는다.
- 공개 GitHub 포크 생성·업스트림 PR은 사용자 확인 후에만. main 푸시·강제 푸시 금지.
- 전역 `happy` 교체는 데몬 재시작 = 실행 중 폰 세션 전부 종료. 사용자에게 알리고 시점을 받는다.
- adb는 USB로만. `JAVA_HOME=/opt/homebrew/opt/openjdk@21`, SDK `sdk.dir=/opt/homebrew/share/android-commandlinetools`.
- iOS·서버 변경·스토어 배포는 하지 않는다.

## Review Focus

1. 턴 마지막 도구 뒤·`result` 직전에 보낸 메시지: SDK가 새 턴으로 처리한다. 앱엔 "완료" 푸시가 먼저 갈 수 있다(알려진 한계, 1단계 기록).
2. 작업 중 모델·plan 모드를 바꾼 메시지: 현재 턴이 끝난 뒤 재시작해서 전달돼야 한다(SDK 입력을 닫아도 턴은 끝까지 감 — 실측).
3. claudeRemote가 죽는 순간 도착한 메시지: 버려지지 않고 다음 실행에 전달(1단계 테스트로 고정).
4. 3단계 `task` 이벤트를 스토어판 앱이 받을 때: 모르는 이벤트로 버려야 한다(크래시 금지).
5. 4단계 HTML 미리보기의 상대 경로 자원과 큰 파일: `readFile` 실패 시 빈 화면 대신 오류 표시.

### Task 1: 작업 중 전달 + 최신 모델 정책 (CLI) — 완료

커밋 `4ce11fe`, `ee58b02` (브랜치 `remote-ux`).

- `src/claude/claudeRemote.ts`: 쿼리 생성 직후 `pumpMessages()`가 `nextMessage()`를 계속 기다려 받는 즉시 SDK 입력에 넣는다. `null`이면 입력을 닫는다(턴은 끝까지 감). 쿼리가 닫힌 뒤 받은 메시지는 `onUndeliverable`로 돌려준다. 최상위 assistant 메시지가 오면 thinking을 다시 켠다.

- `src/claude/sdk/latestModel.ts`: `resolveLatestModel(model, env)` — `claude-(opus|sonnet)-<숫자>…[1m]?` → `opus`/`sonnet`(+`[1m]`). `HAPPY_MODEL_POLICY=pinned`면 그대로. `sdk/query.ts`의 model·fallbackModel에 적용.
- 테스트: `claudeRemote.test.ts` steering 5개, `latestModel.test.ts` 5개. 전체 단위 테스트 1006개 중 1개 실패는 `/tmp/package.json`(다른 작업이 남긴 파일) 탓의 환경 문제.

### Task 4 (3단계): 작업 패널 — 완료

- 세션 프로토콜(`happy-wire`)은 건드리지 않는다. 스토어판 앱이 모르는 `t`는 조용히 버려지므로, 상태는 세션 메타데이터로 싣는다.
- CLI `claude/utils/taskTracker.ts`: SDK `task_started/progress/updated/notification`을 작업 상태로 접는다. 진행 중 + 끝난 지 15분 이내, 최대 30개. `ambient`·`skip_transcript`는 개수에서 뺀다.
- CLI `claude/utils/taskPublisher.ts`: `metadata.remoteTasks`(목록)와 `metadata.activity`(앱의 4그룹 개수)를 처음엔 즉시, 이후엔 2초 모아 갱신. 최상위 백그라운드 작업·워크플로우가 끝나면 대화에 완료 카드(세션 `message` 이벤트).
- 앱 `model/RemoteTasks.kt`: `raw["remoteTasks"]`를 느슨하게 읽는다(깨진 항목만 건너뜀). `ui/session/RemoteTaskPanel.kt`: 입력창 위 막대("2 tasks running · Agent 1 · Shell 1") → 시트(트리, 상태·경과·토큰·마지막 도구·요약). 문자열은 10개 언어.

### Task 5 (4단계): HTML 미리보기와 메모 — 완료

- `ui/files/HtmlPreview.kt`: `.html/.htm`은 Rendered 탭이 기본. WebView는 스크롤 Column 밖에서 화면을 차지하고 스스로 스크롤한다.
- 페이지는 `https://happy-file.invalid/<파일 폴더>/` 아래에서 열린다. 그 호스트로 가는 요청만 `shouldInterceptRequest` → 세션 `readFile` RPC(E2E 릴레이)로 맥에서 읽는다. 10초 넘으면 404.
- 네트워크 정책: 외부 자원(CDN 스크립트·폰트)은 브라우저처럼 허용한다(아티팩트 페이지와 같은 선택). 그 대가로 페이지 JS가 맥 파일을 읽어 밖으로 보낼 수 있으므로, 읽기를 좁힌다:
  - 세션 폴더 안(세션 밖 파일이면 그 파일의 폴더 안)만. `..`로 벗어나면 거절.
  - 이름이 `.`으로 시작하는 폴더·파일 거절(`.env`, `.git`).
  - 확장자 화이트리스트: html·htm·css·js·mjs·그림(png jpg jpeg gif webp avif bmp ico svg)·폰트(woff woff2 ttf otf). `.json` 등 데이터는 거절.
  - GET만. `file://`·content 접근 꺼짐. 다른 곳으로의 링크 탭은 외부 브라우저로.
- 메모: 오른쪽 아래 Memo 버튼. 페이지에서 글을 선택하면 "Memo on selection"이 되어 선택 글을 인용한다. 메모는 "Memo on <절대경로>, about “인용”: <메모> / Update the file to address it." 형태(폰 언어)로 세션에 일반 메시지로 보낸다. 작업 중이면 Task 1의 작업 중 전달로 다음 도구 경계에서 반영된다.
- 채팅의 파일 경로 링크는 이 단계에서 하지 않았다(Task 6 이후 후보).

### Task 6 (5단계): 히스토리 검색과 실행 모델 — 완료

- 홈 머리줄의 검색 버튼 → `SessionSearchRoute`. 세션의 제목·요약·폴더·이름·브랜치·호스트·컴퓨터 이름·실행 모델에서 먼저 찾고(최근 활동순), 그다음 이 폰에 저장된 메시지 본문에서 찾는다(`HappyStore.messagesContaining`, LIKE, 2자 이상, 최대 400건). 본문 일치는 세션당 한 줄, 앞뒤 40자 발췌. 검색은 폰 밖으로 아무것도 보내지 않는다.
- 발췌는 메시지 JSON의 값만 본다. `type`·`role`·`id`·`uuid`·`model` 같은 기록용 키는 건너뛴다.
- 실행 모델: CLI가 SDK `init`의 `model`을 `metadata.runningModel`로 올린다. 앱은 Rig 정체성이 없을 때 세션 행·세션 정보·헤더에 그 값을 보인다. 이걸로 폰에서 Opus 5.5로 도는지 바로 확인한다.
- 전달 상태 표시는 앱에 이미 있어(`ui/chat/MessageDelivery.kt`) 따로 만들지 않았다.
- 남은 후보: 채팅의 파일 경로 링크, 앱의 한국어 번역(현재 9개 언어 + 영어).

### Task 7 (6단계): 채팅 안 미디어 바로 보기 — 완료

- 에이전트의 글과 도구 호출(Write·Read·Bash 등의 입력)에 나온 그림(png·jpg·gif·webp·bmp)·영상(mp4·mov·m4v·webm)·HTML 경로를 메시지 아래 타일로 보인다. 접힌 작업의 미디어는 답변 아래로 모인다. 탭하면 앱 안 뷰어로 열린다. 직접 내려받거나 저장할 필요가 없다.
- CLI `readFileChunk`: 3 MB 이하 조각 읽기(릴레이 8 MB 한도). 작업 폴더 밖은 그림·영상은 어디서나, 웹 페이지 파일은 숨김 폴더가 아닐 때만 허용하고, 실제 경로(심링크 해석)로 판정한다. 앱은 2 MB씩 받고, 이 기능이 없는 CLI면 `readFile` 한 번으로 받는다.
- 영상은 캐시에 받는 동안 진행률을 보이고, 다 받으면 앱 안에서 재생한다(VideoView, 파일 제공자 경유).

### Task 8 (7단계): 컴퓨터 화면 캡처 — 완료

- 채팅 머리줄의 화면 버튼 → 시트: 스크린샷, 5·15·30초 녹화. CLI가 macOS `screencapture`로 `~/.happy/captures`에 쓴다. 녹화는 비동기로 시작하고 앱이 `captureStatus`로 끝났는지 묻는다(RPC 30초 제한 때문). 다 되면 바로 뷰어로 열리고, "Claude에게 물어보기"는 파일 경로를 담은 메시지를 보낸다.
- 첫 캡처에는 happy를 실행하는 앱의 화면 기록 권한이 필요하다(시스템 설정 → 개인정보 보호 및 보안 → 화면 기록).

### Task 9 (8단계): 실시간 화면(WebRTC) — 완료

- 시트의 "실시간 화면" → 전체 화면 뷰어. 폰이 수신 전용 offer를 만들어 세션 RPC(`screenStreamStart`, 암호화 릴레이 경유)로 보내고, CLI가 werift로 answer한다. 화면은 ffmpeg(avfoundation → VP8, 2초 GOP)에서 로컬 UDP RTP로 werift에 들어가 폰으로 직접(P2P, DTLS-SRTP) 간다. STUN(`stun.l.google.com`)은 주소만 안다. TURN이 없으므로 직접 연결이 10초 안에 안 되면 약 1초에 1장씩 JPEG(`screenFrame`)를 릴레이로 받는다.
- 스트림과 ffmpeg는 중지 요청, 연결 실패·종료(끊김 10초), 10분 제한, ffmpeg 종료, 프로세스 종료 때 끝난다. 한 번에 하나만 돈다.
- CLI 테스트는 테스트 패턴을 화면 대신 넣어 werift 수신 피어까지 VP8 키프레임이 오는지, 중지하면 멈추는지 확인한다.
