# 맥의 Claude 백그라운드 세션을 폰에서 이어 쓰기 설계

## 의도

사용자는 맥에서 `claude --bg`로 띄운 Claude Code 백그라운드 세션(`claude agents`에 보이는 것)을 여러 개 돌린다. 지금 Jarvis 앱은 Happy가 직접 띄운 세션만 보여 준다. 맥에서 이미 돌고 있는 세션은 폰에서 보이지도 않고 이어 쓸 수도 없다.

사용자의 말로는 "클로드 리모트처럼 하나의 세션을 두 곳에서 다 접근 가능하도록"이다(2026-11-09). 원하는 것은 Remote Control과 같은 **경험**이다. Remote Control 기능 자체는 쓰지 않는다. 맥에서 할 수 있는 응답은 폰에서도 할 수 있어야 한다.

사용자가 다시 정리한 기준(2026-11-09): "하나의 세션에 폰과 맥북 둘 다 접근 가능하고, 폰에서 입력하면 맥북에도 그 답변이 본인이 한 것처럼 뜨고, 맥북에서 특정 물음에 대해 선택하면 폰에서도 그렇게 한 것처럼 뜨고 진행돼야 한다." 즉 어느 쪽에서 한 입력이든 양쪽 화면에 **사용자 본인의 입력**으로 똑같이 보이고, 세션은 하나로 이어진다.

원하는 경험은 다음과 같다. 맥북에 Claude 세션이 3개 돌고 있다. 폰에서 Jarvis를 열면 그 3개가 보이고, 하나를 누르면 지금까지의 대화가 보인다. 그대로 이어서 말할 수 있다. 맥에서도 같은 세션을 계속 `claude attach`로 쓸 수 있다. **두 쪽 모두 살아 있어야 한다.** 폰에서 썼다고 맥 세션이 멈추거나 다른 세션으로 갈라지면 안 된다.

## 목표

1. **목록.** 앱에서 맥별로 지금 돌고 있는 Claude 백그라운드 세션을 본다. 이름, 폴더, 상태(일하는 중 / 대기 / 권한 기다림)가 보인다.
2. **열기.** 하나를 누르면 기존 채팅 화면으로 열린다. 그 세션의 지금까지 대화가 보이고, 이후 대화도 실시간으로 들어온다. 맥에서 입력한 말도 들어온다.
3. **이어 말하기.** 폰에서 보낸 메시지가 그 세션에 사용자 입력으로 들어가 Claude가 답한다.
4. **권한 응답.** 세션이 도구 권한을 물으면 폰에 기존 권한 카드와 알림이 뜬다. 폰에서 허용·거부할 수 있다. 맥에서 먼저 답하면 폰 카드도 그 답(허용/거부)으로 바뀐다.
5. **선택지 질문과 계획 승인.** 세션이 AskUserQuestion으로 선택지를 내밀거나 ExitPlanMode로 계획 승인을 물으면, 폰의 기존 질문 카드와 계획 승인 카드에 뜨고 폰에서 답할 수 있다. 맥에서 먼저 답하면 폰 카드도 맥에서 고른 답으로 바뀌고 진행이 이어진다.
6. **공존.** 위 동작 내내 세션은 `claude agents` 목록에 그대로 남고, 맥에서 `claude attach`로 계속 쓸 수 있다.

## 하지 않을 것

- **Claude Remote Control 사용.** 절대 쓰지 않는다. 세션은 항상 이 맥의 Claude Code 프로세스 그대로다.
- **세션 간 메시지 소켓(peer socket) 사용.** 그 경로로 들어간 말은 "다른 Claude 세션이 보낸 말"로 취급돼 사용자 권한이 없다. 실험에서 확인했다.
- **세션을 멈추고 Happy로 다시 띄우기(stop + resume).** 그러면 `claude agents`에서 빠지고 맥 쪽 세션이 사라진다.
- **일반 터미널(interactive) 세션.** v1은 `kind: background`만 다룬다. cmux 창에서 직접 띄운 세션은 붙을 통로가 없다. 새 세션을 처음부터 Happy로 띄우고 싶으면 `alias claude=happy` 같은 사용자 쪽 방법을 안내만 한다.
- **Happy 서버 수정.** 공식 중계 서버를 그대로 쓴다.
- **화면 내용 해석.** 터미널 화면은 키 입력을 넣는 데만 쓴다. 대화 내용은 기록 파일(transcript)에서 읽는다. 단, 권한 창이 실제로 떠 있는지 확인하는 데는 화면 글자를 본다(아래 "권한").

## 실패로 보는 것

- 폰에서 쓴 뒤 맥 세션이 사라지거나, 갈라진 새 세션이 생기는 것.
- 폰에서 보낸 말이 사용자 입력이 아닌 다른 경로로 들어가는 것.
- 권한 답 "1"이 권한 창이 아닌 입력창에 글자로 들어가는 것. 맥에서 먼저 답한 뒤 폰이 늦게 답하는 경우가 대표적이다.
- 같은 메시지가 폰 화면에 두 번 보이는 것. 폰이 보낸 말이 기록 파일을 거쳐 다시 올라오는 경우다.
- 기존 Happy 세션(Happy가 직접 띄운 것)의 동작이 바뀌는 것.

## 제약

- 대상 Claude Code: 이 맥에 설치된 버전. `claude agents --json`, `claude attach <id>`가 있어야 한다. 이 두 명령이 없으면 기능을 숨긴다.
- 새 npm 의존성은 되도록 추가하지 않는다. pty가 필요하면 아래 "보이지 않는 터미널"의 순서대로 고른다.
- 업스트림 변경을 합치기 쉽도록 새 코드는 새 파일에 모은다. CLI의 기존 파일은 등록과 짧은 거절 조건 수준으로만 고친다. 안드로이드 앱은 화면 구조상 기존 UI 함수를 고쳐야 하므로, 새 컴포저블은 새 파일에 두고 기존 화면에는 최소한의 연결만 한다(나의 결정).
- **어느 `claude`를 쓰나.** 데몬은 launchd 아래에서 돌아 PATH가 다르다. 저장소에는 Agent SDK에 묶인 Claude도 있다. 하지만 `agents`·`attach`는 백그라운드 세션을 띄운 사용자의 `claude`로 불러야 한다. 데몬은 로그인 셸에서 `command -v claude`로 그 경로를 한 번 찾아 쓴다. 묶인 Claude는 쓰지 않는다(나의 결정).
- **배포.** 이 기능은 맥의 전역 CLI를 포크 빌드로 바꿔야 동작한다. 교체 시점은 사용자가 따로 승인한다. 앱은 옛 데몬이 `list-claude-agents`를 모르면 섹션을 숨긴다.
- 포크 저장소에는 개인·회사 정보와 키를 넣지 않는다. 테스트 픽스처의 경로·이름은 가짜 값을 쓴다.

## 실험으로 확인한 사실 (2026-11-09)

맥에서 일회용 백그라운드 세션으로 확인했다. 설계의 근거다.

- `claude agents --json`은 TTY 없이 동작한다. 항목마다 `pid, id, cwd, kind('background'|'interactive'), startedAt, sessionId, name, status('idle'|'busy'|'waiting'), state('working'|'done')`가 있다.
- `~/.claude/sessions/<pid>.json`에 같은 `status`가 실시간으로 바뀐다.
- 기록 파일은 `~/.claude/projects/<slug>/<sessionId>.jsonl`이다. slug는 `resolve(cwd)`에서 영숫자와 `-` 외 문자를 `-`로 바꾼 것이다. Happy의 `getProjectPath`와 같다.
- 보이지 않는 pty에서 `claude attach <id>`를 띄워 글자와 `\r`을 넣으면 진짜 사용자 입력으로 들어간다. 세션이 답하고, 기록 파일에 사용자 메시지로 남는다.
- attach 프로세스를 죽이면 붙기만 끝나고 세션은 살아 있다. 왼쪽 화살표는 붙기를 끝내지 않고 에이전트 목록 화면으로 간다.
- attach는 여러 개를 동시에 붙일 수 있다. 한쪽에서 넣은 말과 답이 다른 쪽 화면에도 실시간으로 보였다. 따라서 맥에서 attach 중이어도 폰 입력이 들어간다.
- 권한 창이 뜨면 `status`가 `waiting`이 된다. 기록 파일의 마지막 항목은 결과(tool_result)가 없는 assistant `tool_use`(도구 이름과 입력 포함)다. attach 화면에는 "Do you want to create X? ❯ 1. Yes / 2. Yes, and allow… / 3. No"가 보인다. 새로 붙어서 `1`을 넣으면 승인되고 `status`가 `idle`로 돌아온다.
- `claude --bg`는 신뢰된 폴더에서만 시작된다. 이미 돌고 있는 세션에 붙는 데는 상관없다.

## 접근 방식

검토한 길은 넷이다.

| 방식 | 내용 | 결론 |
|---|---|---|
| A. 거울 세션 + attach 입력 (선택) | 맥 데몬이 세션 목록을 알려 준다. 사용자가 고르면 그 세션의 거울 Happy 세션을 만든다. 기록 파일을 읽어 폰에 올리고, 폰의 말은 보이지 않는 pty의 `claude attach`로 타이핑해 넣는다. | 맥 세션을 그대로 두고 폰에서 쓸 수 있는 유일한 길. 실험으로 확인했다. |
| B. 세션을 Happy로 옮기기 | 세션을 멈추고 `happy claude --resume`으로 다시 띄운다. | `claude agents`에서 빠져 맥 쪽이 사라진다. "둘 다 살아 있기"와 맞지 않는다. |
| C. 세션 간 메시지 소켓 | `/tmp/cc-socks/<pid>.sock`으로 말을 넣는다. | 사용자 권한 없는 "다른 세션의 말"로 들어간다. |
| D. cmux 창 바꿔치기 | 터미널 창을 Happy로 교체한다. | interactive 창에만 통하고 백그라운드 세션엔 창이 없다. |

사용자는 A를 골랐다(2026-11-09, "claude agents!" 범위 확정, 실험 승인 후).

## 구조

### 1. 맥 데몬: 세션 목록 (머신 RPC)

- 새 머신 RPC `list-claude-agents`. 데몬이 `claude agents --json`을 실행해 `kind === 'background'`만 남긴다. 반환은 `{ agents: [{ id, sessionId, name, cwd, status, state, startedAt, mirrorSessionId? }] }`. `mirrorSessionId`는 이미 거울이 있으면 그 Happy 세션 ID다.
- `claude`가 없거나 명령이 실패하면 `{ agents: [], unavailable: "<이유>" }`를 반환한다. 앱은 섹션을 숨기거나 안내 한 줄을 보인다.
- 등록 위치는 기존 머신 RPC 옆이다(`api/apiMachine.ts`의 `spawn-happy-session` 등과 같은 방식, 데몬 `setRPCHandlers` 경유).

### 2. 맥 데몬: 열기 (머신 RPC)

- 새 머신 RPC `open-claude-agent { id }`. 반환은 `{ type: 'success', sessionId }` 또는 `{ type: 'error', errorMessage }`. 앱은 받은 `sessionId`로 기존 채팅 화면을 연다.
- 같은 백그라운드 세션에 거울이 이미 있으면 새로 만들지 않고 그 ID를 돌려준다. 거울의 기준 키는 **에이전트 `id`**다. `sessionId`는 맥에서 `/clear`하면 바뀌므로 키로 쓰지 않는다.
- **다시 열기는 고정 태그만으로는 안 된다.** dataKey 암호화 계정에서는 `getOrCreateSession`(`api/api.ts`)이 부를 때마다 새 키를 만든다. 그래서 기존 세션을 같은 태그로 받으면 복호화에 실패한다(코드로 확인). 거울은 처음 만들어질 때 다른 자식 세션처럼 데몬에 신고(`notifyDaemonSessionStarted`)한다. 그러면 데몬이 이미 하는 대로 암호화 키·방식과 메타데이터(`claudeAgentId` 포함)를 세션 저장 파일에 남긴다(`persistSession`). 다시 열 때는 데몬이 이미 쓰는 재연결 방식(저장된 암호화 데이터 + `HAPPY_RECONNECT_*` 환경변수, `daemon/run.ts` 233·855행 부근)으로 같은 세션에 붙는다(나의 결정). 이 파일은 데몬이 재시작돼도 남는다.
- 거울은 데몬이 띄우는 **자식 프로세스**로 돈다(나의 결정: 데몬이 `happy claude` 자식을 띄우는 기존 방식과 같고, 세션 단위 RPC 등록(`registerCommonHandlers(metadata.path)`)을 그대로 쓸 수 있다). 예: `happy claude-agent-mirror <id>`. 데몬은 기존 자식 세션처럼 추적하고, `stop-session`이 오면 **거울만** 끝낸다. 백그라운드 세션은 건드리지 않는다.

### 3. 거울 세션: 대화 올리기

- 메타데이터: `flavor: 'claude'`, `path`·`cwd` = 백그라운드 세션 cwd, `claudeSessionId` = 백그라운드 sessionId, `startedBy: 'daemon'`, 그 외 필수 필드는 `runClaude.ts`와 같다. 거울 표시용 `claudeAgentId: <id>`를 추가한다. 앱은 이 값으로 거울을 알아본다. 공식 앱은 모르는 필드를 무시한다.
- `createSessionScanner({ sessionId: null, workingDirectory: cwd, onMessage })` 뒤 `onNewSession(bg sessionId)`로 기존 기록부터 다시 읽어 올린다. 올리는 함수는 로컬 모드와 같은 `sendClaudeSessionMessageFromLocalTranscript`다.
- 거울을 다시 열 때 이미 올린 기록을 또 올리지 않는다. 이미 올린 마지막 기록의 uuid를 거울 전용 파일 `<happyHomeDir>/claude-agent-mirrors/<agentId>.json`(`{ happySessionId, lastUuid }`, 권한 0600)에 저장해 두고, 그 뒤부터만 올린다. 데몬 파일과 따로 두는 이유는 두 프로세스가 같은 파일을 동시에 쓰지 않게 하기 위해서다.
- **세션 전환 따라가기.** 맥에서 `/clear` 등으로 백그라운드 세션의 `sessionId`가 바뀔 수 있다. 거울에는 Claude 훅이 없으므로, 거울이 `claude agents --json`을 주기적으로 보고 같은 `id`의 `sessionId`가 바뀌면 `onNewSession(새 sessionId)`로 새 기록 파일을 따라간다(나의 결정). 메타데이터의 `claudeSessionId`도 갱신한다.
- **중복 방지.** 폰이 보낸 말은 이미 서버에 사용자 메시지로 있다. 그래서 거울이 타이핑한 말이 기록 파일에 사용자 메시지로 다시 나타나면 올리지 않는다. 거울이 타이핑한 텍스트를 대기열에 기억해 두고, 기록 파일의 다음 사용자 메시지와 같으면 건너뛴다. 맥에서 직접 입력한 말은 대기열에 없으므로 그대로 올라간다.

### 4. 거울 세션: 폰의 말 넣기

- `onUserMessage`로 받은 텍스트를 직렬 대기열에 넣는다. 하나씩 처리한다: 보이지 않는 pty에서 `claude attach <id>` 시작 → 화면이 그려질 때까지 대기 → 텍스트 입력 → `\r` → 잠깐 대기 → attach 종료.
- 여러 줄 텍스트는 bracketed paste(`ESC[200~ … ESC[201~`)로 붙여 넣은 뒤 `\r`을 보낸다. 그냥 줄바꿈을 보내면 첫 줄에서 전송돼 버린다. 실제 동작은 빌더가 실험으로 확인한다.
- 세션이 `busy`일 때 온 말: 그대로 타이핑한다. Claude Code는 일하는 중 입력을 대기열에 넣어 다음 경계에서 반영한다. 이 동작이 확인되지 않으면 `idle`이 될 때까지 기다렸다 보낸다. 어느 쪽인지 빌더가 확인한다.
- 매번 붙었다 떨어지는 방식은 나의 결정이다. 계속 붙어 있으면 "맥 attach와 동시"는 되지만 거울 프로세스가 화면 출력을 계속 받아 버려야 한다. 매 메시지 1~2초 지연은 감수한다.
- 이미지·파일 첨부는 v1에서 받지 않는다. 앱이 첨부를 보내면 "이 세션은 텍스트만 받습니다"로 답한다.
- **중단(Esc).** 앱의 중단 버튼은 attach에서 `Esc`를 한 번 보내는 것으로 처리한다. 맥에서 Esc를 누르는 것과 같다(나의 결정).
- **슬래시 명령.** 폰에서 `/compact` 같은 텍스트를 보내면 그대로 타이핑한다. 맥에서 직접 치는 것과 같기 때문이다(나의 결정). `/clear`로 세션이 바뀌면 3절의 "세션 전환 따라가기"가 처리한다.
- 폰 텍스트의 제어 문자(ESC 등)는 타이핑 전에 지운다. 그래야 폰에서 보낸 글자가 터미널 키 입력으로 해석되지 않는다.
- 입력창이 비었는지는 색 정보까지 담은 화면(`capture-pane -p -e`)으로 판단한다. 빈 입력창에 흐리게 뜨는 제안 글자는 빈 칸으로 본다.
- 입력창 위에 세션 설문(`1: Bad 2: Fine 3: Good 0: Dismiss`)이 떠 있으면 `0`으로 닫은 뒤 넣는다. 그래야 숫자로 시작하는 폰 메시지가 설문 답으로 먹히지 않는다.

### 5. 보이지 않는 터미널(pty)

attach는 진짜 터미널을 요구한다. **tmux를 쓴다**(2026-11-09 결정).

- 근거:
  - macOS `script`는 자식에게 터미널은 주지만, Node에서 파이프로 넣은 입력이 전달되지 않았다(시험 결과 출력 없음).
  - tmux는 이 맥에 있다(`/opt/homebrew/bin/tmux`).
  - `capture-pane -p`로 지금 화면의 글자를 깔끔하게 읽을 수 있어 권한 창 확인에 알맞다.
  - `paste-buffer -p`로 여러 줄을 bracketed paste로 넣을 수 있다.
- 사용자의 tmux 세션과 섞이지 않도록 전용 소켓 `tmux -L jarvis-agents`를 쓴다.
- tmux가 없으면 `list-claude-agents`가 `unavailable: "tmux-missing"`을 돌려준다. 앱은 안내 한 줄을 보인다.
- 새 npm 의존성은 추가하지 않는다.

터미널 크기는 120×40으로 고정한다(실험값).

### 5-1. 맥에 열어 둔 cmux 창을 먼저 쓰기 (2단 방식)

사용자가 cmux 창에서 그 세션에 `claude attach <id>`로 붙어 있으면, 폰의 입력과 답을 그 창에 넣는다. 그러면 폰에서 한 일이 맥에서 보고 있는 바로 그 창에 찍힌다. 그런 창이 없거나 쓰면 안 되는 경우에만 5절의 전용 tmux를 쓴다(사용자 결정, 2026-11-09).

- **창 찾기.** 인자가 `attach <agentId>`로 끝나는 `claude` 프로세스를 찾고(cmux가 띄운 `claude`는 앞에 `--session-id`, `--settings`가 붙지만 끝은 그대로다), `cmux top --all --processes --format tsv`에서 그 PID가 속한 terminal surface를 찾는다. 전용 tmux(`-L jarvis-agents`) 아래 프로세스는 제외한다. 붙은 창이 여럿이면 가장 최근에 시작한 프로세스의 창을 쓴다. 창을 찾을 때마다 새로 찾는다(창 참조를 오래 들고 있지 않는다).
- **명령.** 화면은 `cmux read-screen --surface <ref>`, 글자는 `cmux send --surface <ref> -- <text>`, 키는 `cmux send-key --surface <ref> <key>`. 창은 절대 닫지 않는다(`close`는 아무것도 안 한다).
- **cmux 창을 쓰지 않는 경우(→ 전용 tmux):**
  - cmux가 없거나, cmux 명령이 하나라도 실패한다(소켓 권한 포함).
  - 폰의 입력을 넣으려는데 그 창의 입력창이 비어 있지 않다. `read-screen`은 색 정보가 없어 흐린 제안 글자와 친 글자를 구별하지 못하므로, 입력창에 글자가 보이면 비어 있지 않은 것으로 본다. 맥에서 쓰던 글에 폰의 말이 섞이지 않게 하기 위해서다.
  - 폰의 텍스트가 여러 줄이거나 역슬래시를 담고 있다. `cmux send`는 `\n`·`\r`·`\t`를 키로 바꾸기 때문이다.
  - 창의 화면을 `classifyScreen`으로 읽을 수 없다.
- **창 크기.** cmux 창 크기는 사용자의 화면에 따라 다르다(예: 99×35). 화면 읽기(`classifyScreen`, `readDialogFromScreen`, `screenMatchesPending`)는 폭과 높이에 기대지 않는다. `dialogFingerprint`는 창 영역에서 공백과 가로줄 문자를 모두 뺀 글자로 계산한다. 그래야 같은 창을 폭이 다른 두 터미널에서 읽어도 지문이 같다.
- **화면 감시(tick).** 대기 중인 창을 알아보는 일은 cmux 창이 있으면 그 화면으로, 없으면 지금처럼 전용 tmux로 한다.
- **권한·질문·계획 답.** 6절의 네 가지 확인을 키를 넣을 바로 그 창의 화면으로 한다. 먼저 cmux 창에서 확인하고, 다 통과하면 거기에 넣는다. 하나라도 어긋나거나 cmux 창이 없으면 전용 tmux를 열어 같은 확인을 하고, 통과하면 거기에 넣는다. 둘 다 어긋나면 지금처럼 거절한다.

### 6. 권한

- 거울은 `~/.claude/sessions/<pid>.json`의 `status`를 지켜본다(감시 간격·방식은 빌더 몫, 1초 안팎이면 충분).
- `waiting`이 되면 거울은 attach 화면과 기록 파일을 함께 본다. 창이 떠 있는 동안 그 `tool_use`가 기록 파일에 아직 없는 경우가 많다(Claude Code 2.1.319 실측: AskUserQuestion과 일부 Write·Edit는 답한 뒤에야 기록된다). 그래서 요청 키를 이렇게 정한다.
  - 기록에 결과 없는 `tool_use`가 있으면 그 `id`.
  - 없으면 `screen:<창 지문>`. 창 지문은 창 영역(첫 가로줄부터 맨 아래 가로줄까지, ANSI 제거, 공백 정리, 상태줄 제외)의 sha1이다.
- 카드 내용(`tool`, `arguments`)은 기록에 있으면 그 입력을, 없으면 화면에서 읽은 것(도구 이름, 대상 파일 이름·명령, 지금 질문과 선택지)을 쓴다. 화면에서 다 읽을 수 없는 창(여러 질문 탭, 잘린 명령, 모르는 문구, 서브에이전트 창)은 답할 수 없는 안내 카드로 보이고 "맥에서 답해 주세요"를 붙인다. 계획 본문은 기록에서 얻었을 때만 보인다. `~/.claude/plans/`는 여러 세션이 함께 쓰므로 추측해서 읽지 않는다.
- 거울은 `agentState.requests[키] = { tool, arguments, createdAt }`를 쓰고 알림을 보낸다. 기존 `PermissionHandler`가 하는 것과 같은 형태라 앱의 권한 카드가 그대로 동작한다.
- 폰이 세션 RPC `permission`으로 답하면 타이핑 직전에 네 가지를 다시 확인한다. 넷 다 맞을 때만 화면에서 읽은 `Yes`/`No` 선택지 번호를 넣는다(창마다 `No`가 2번 또는 3번이다).
  1. `status`가 여전히 `waiting`이다.
  2. 폰에 보여 준 창과 지금 화면의 창이 같다. 창 지문이 같아야 하고, 기록에서 얻은 id가 있으면 지금 대기 중인 `tool_use` id도 같아야 한다.
  3. attach 화면에 해당 종류의 창(권한·질문·계획)이 보인다.
  4. 화면의 창이 폰에 보여 준 그 도구에 관한 것이다. 도구 이름이나 대상 파일·명령을 화면 글자와 맞춰 본다.
- 키는 한 번에 하나씩 600ms 간격으로 넣는다. 숫자 두 개를 한 번에 보내면 하나의 숫자로 읽힌다.
- 하나라도 어긋나면 아무것도 넣지 않는다. 대표적인 경우는 서브에이전트가 권한을 묻는 상황이다. 이때 본 기록의 마지막 `tool_use`는 Task 호출이고, 실제로 묻는 도구는 서브에이전트 기록에 있다. 어긋나면 요청을 완료 처리하고 폰에 "맥에서 답해 주세요"를 보인다. 잘못 허용하는 것보다 답을 못 넣는 쪽으로 실패하게 한다(나의 결정).
- **맥에서 먼저 답한 경우.** 폰 카드는 지우지 않고 "그렇게 답한 상태"로 바꾼다. `status`가 `waiting`에서 벗어나면 거울은 기록 파일에서 그 `tool_use`의 결과(tool_result)를 읽는다. 결과에 따라 `completedRequests[id]`에 `status`와 `decision`을 쓴다(`approved` / `denied`). 그러면 폰에는 폰에서 허용·거부한 것과 똑같이 보인다. 결과가 아직 없으면 잠시 더 기다린다. 끝내 없으면 `canceled`로 쓴다.
  - `screen:` 요청이면 창이 사라진 뒤 기록에 새로 나타난 `tool_use` 가운데 저장해 둔 화면과 맞는 것(`screenMatchesPending`)을 찾아 그 결과로 판정한다. `completedRequests['screen:…']`에 결과를 쓰고 `toolUseId`는 비워 둔다. 그래야 카드가 그 자리에서 닫힌다. 완료된 `screen:` 카드와 뒤이어 오는 실제 도구 메시지가 겹쳐 보이지 않게 하는 것은 앱이 맡는다(8절).
- **폰에서 답한 경우.** 맥의 attach 화면에는 맥에서 키를 누른 것과 똑같이 반영된다. 실제로 키가 그 창에 들어가기 때문이다.
- 일반 도구 권한에서는 "이번 세션 동안 항상 허용"(2번)과 응답의 `mode`·`allowTools`·`updatedInput`을 v1에서 쓰지 않는다. 허용·거부만 한다. 선택지 질문과 계획 승인은 6-1절을 따른다.

### 6-1. 선택지 질문(AskUserQuestion)과 계획 승인(ExitPlanMode)

사용자 결정(2026-11-09): 폰에서도 답한다.

- 둘 다 세션을 `waiting`으로 만든다. 요청 키와 카드 내용은 6절 규칙을 따른다(질문은 기록에 답한 뒤에야 나타나는 경우가 많아 대개 `screen:` 키와 화면에서 읽은 질문·선택지가 된다). 앱은 도구 이름을 보고 기존 질문 카드와 계획 승인 카드를 띄우므로 앱 쪽 새 UI는 필요 없다.
- 앱의 답은 기존 형태 그대로 온다. 거울은 이를 attach 키 입력으로 바꾼다. 일반 Happy 세션의 처리 방식은 `claude/utils/permissionHandler.ts`에 있다.
  - **질문:** `updatedInput`에 고른 답이 담겨 온다.
  - **계획:** `approved`와 승인 후 권한 모드 `mode`가 온다.
- 매핑 규칙:
  - **질문:** 질문마다 고른 선택지의 번호를 넣고 다음 질문으로 넘어간다. 여러 개 고르기는 해당 번호들을 토글한 뒤 `Tab`으로 확정한다. 질문이 여럿이면 마지막에 확인 화면에서 `1`(Submit)을 누른다. "기타"에 쓴 자유 입력은 넣지 않고 "맥에서 답해 주세요"로 보낸다. 거부(취소)는 `Esc`다.
  - **계획:** 이 버전의 계획 창은 `1 Yes, and use auto mode / 2 Yes, manually approve edits / 3 Tell Claude what to change`이다. 1번은 앱이 보내는 어떤 모드보다 넓으므로, 승인은 `mode`와 상관없이 항상 2번(수동 승인)이다. 거부는 3번이고, 이유(`reason`)가 있으면 이어서 타이핑한 뒤 `Enter`를 누른다.
- 실제 화면의 번호·키·확정 방식은 Claude Code 버전마다 다를 수 있다. 그래서 **빌더가 일회용 세션으로 먼저 실험해** 확정하고, 그 화면 글자를 픽스처로 남긴다.
- 권한과 같은 안전장치(6절의 네 조건)를 둔다. 화면에 그 질문·계획 창이 손대지 않은 상태로 보여야 한다(질문은 아무것도 고르지 않은 첫 화면, 계획은 이유 칸이 빈 상태). 하나라도 어긋나면 넣지 않고 "맥에서 답해 주세요"를 보인다.
- **맥에서 먼저 답한 경우.** 6절과 같이 기록 파일의 결과를 읽어 완료 처리한다. 선택지 질문은 결과에 담긴 고른 답을 폰 질문 카드에 "그 답을 고른 상태"로 보이게 한다. 계획 승인은 승인·거부 상태로 보이게 한다. 앱의 질문 카드가 고른 답을 어디서 읽는지(완료 요청의 필드인지, 대화의 tool_result인지)는 빌더가 앱 코드에서 확인해 맞춘다. 기준은 "폰에서 고른 것과 똑같이 보인다"이다.
- 여러 질문 중간에 맥에서 일부를 답한 경우처럼 화면 상태가 예상과 다르면, 이어서 넣지 않고 같은 방식으로 멈춘다.

### 7. 거울의 수명

- 거울은 백그라운드 세션이 살아 있는 동안만 돈다. `claude agents --json`에서 그 id가 사라지면 거울은 Happy 세션을 끝남 상태로 바꾸고 종료한다(감시 간격은 빌더 몫).
- 데몬이 재시작되면 열려 있던 거울을 다시 띄우지 않는다. 사용자가 앱에서 다시 누르면 같은 Happy 세션으로 다시 열린다(고정 태그 덕분).
- 폰에서 거울 세션을 보관(archive)하거나 멈추면 거울만 끝난다. 맥 세션은 그대로다.

### 8. 앱

- 홈 목록에 맥별 "Claude 백그라운드 세션" 섹션을 추가한다. 온라인인 머신마다 `list-claude-agents`를 부르고, 이름·폴더 끝부분·상태를 한 줄로 보인다. 홈에 들어올 때와 당겨서 새로고침할 때 다시 부른다.
- 이미 거울이 있는 항목은 기존 세션 행과 겹치지 않게 한 번만 보인다. 섹션의 항목을 누르면 `open-claude-agent` → 받은 `sessionId`로 채팅 화면을 연다.
- 거울 세션의 채팅 화면은 기존 화면 그대로다. 단, 거울에서 안 되는 조작은 숨기거나 막는다. 대상은 모델 바꾸기, 권한 모드 바꾸기, 첨부, 그리고 **다시 시작(resume)·포크·사이드챗·복제·되감기**다. 뒤의 다섯 가지는 메타데이터의 `claudeSessionId`로 `happy claude --resume`을 띄우거나 기록 파일을 고친다. 그러면 살아 있는 맥 세션에 두 번째 Claude 프로세스가 붙어 세션이 갈라진다. 앱은 `claudeAgentId`가 있는 세션에서 이 조작들을 숨긴다. 데몬의 `resume-happy-session`도 `claudeAgentId`가 있는 세션이면 거절한다. 기존 처리기에 짧은 거절 조건만 추가한다(나의 결정, 공식 앱에서 눌러도 안전하도록). fork·duplicate·rewind RPC는 Happy 세션 ID 없이 폴더와 Claude 세션 ID만 받는다. 게다가 기록의 사본으로 새 Claude 세션을 만들 뿐 살아 있는 세션을 건드리지 않으므로, 데몬에서는 막지 않고 앱에서만 숨긴다. 상단에는 "맥 백그라운드 세션" 표시를 단다.
- 거울 세션의 `screen:` 권한 카드: 앱은 요청 id를 도구 메시지와 잇는 키로 쓰므로(`toolUseId ?: id`), `screen:` 카드는 독립된 도구 메시지로 뜬다. 완료된 `screen:` 카드 뒤에 같은 도구의 실제 메시지가 오면 둘이 겹쳐 보이지 않게 한다. 계획 승인 카드의 "자동 수락" 선택지는 거울에서 숨기거나 수동 승인과 합친다(6-1절, 승인은 항상 수동 승인).
- 요청 함수는 `sync/MachineOps.kt`에 다른 머신 RPC와 같은 모양으로 추가한다.
- 새 문구는 `happy-i18n` 카탈로그에 넣고 `generate.mjs`로 생성한다.

## 시험

- **단위(CLI):** `claude agents --json` 출력 파싱(배경만 거르기, 잘못된 JSON, 빈 목록). 결과 없는 마지막 `tool_use` 찾기. 중복 방지 대기열(폰 말은 건너뛰고 맥 말은 올림). 권한 답 직전 재확인(세 조건 중 하나라도 어긋나면 타이핑 안 함). 태그로 같은 거울 재사용.
- **단위(앱):** `list-claude-agents` 응답 파싱, `unavailable`일 때 섹션 처리, 거울 화면에서 막힌 조작.
- **통합(맥, 수동 또는 스크립트):** 신뢰된 폴더에서 일회용 `claude --bg --model haiku` 세션을 띄운다. 목록 → 열기 → 기록이 올라옴 → 폰 말 넣기 → 답이 올라옴 → 맥에서 `claude attach`로 같은 대화 확인 → 권한 창 허용/거부 → 맥에서 먼저 답하기 → 선택지 질문(단일·여러 개·기타)과 계획 승인·거부를 폰에서 답하기 → `claude stop`·`rm` 후 거울 종료까지 확인한다. 사용자의 실제 세션에는 절대 입력하지 않는다.
- **폰 확인:** 실기기(USB adb)에서 위 흐름을 한 번 돌린다.

## 위험

- **attach 화면은 공개 약속이 아니다.** Claude Code 버전이 바뀌면 권한 창 번호나 문구가 바뀔 수 있다. 권한 답 직전의 화면 확인이 어긋나면 넣지 않는 쪽으로 실패하게 한다. 이렇게 하면 잘못 허용되는 일은 없다.
- **신뢰 폴더.** 붙기에는 상관없지만, 통합 시험용 세션을 띄울 때는 신뢰된 폴더가 필요하다.
- **여러 맥.** 맥마다 데몬이 자기 세션만 보고한다. 앱은 머신별로 나눠 보인다.
- **지연.** 메시지마다 attach를 새로 붙여 1~2초 늦다.

## 빌더에게 맡기는 것

- pty 방식의 최종 선택(위 순서 안에서).
- `status` 감시와 세션 소멸 감시의 방식·간격.
- 거울 전용 파일의 쓰기 방식(원자적 쓰기 등).
- busy 중 입력을 바로 넣을지 기다릴지(Claude Code 동작 확인 후).
- 섹션의 시각 디자인(기존 홈 행 스타일을 따른다).

## 확인 기록

실기기(USB adb로 붙인 안드로이드 폰, 디버그 앱)와 맥에서, 일회용 배경 세션 `jarvis-e2e`로 확인했다. 맥 쪽은 cmux 창에 연 `claude attach`이고, 그 창을 쓸 수 없을 때는 거울 전용 tmux로 간다.

**확인된 것**

- 앱 홈의 "Claude 백그라운드 세션" 섹션에 상태와 함께 보이고, 누르면 지난 기록과 함께 거울 채팅이 열린다. 제목은 에이전트 이름이다.
- 폰 입력이 맥 cmux 창에 사용자 입력(`❯ …`)으로 뜨고 답이 폰으로 온다. 중복은 없다. 맥에서 입력한 말도 폰에 사용자 말풍선으로 뜬다.
- 권한 창: 폰 허용, 폰 거부, 맥에서 먼저 허용(폰 카드가 허용으로 바뀜). 거울의 권한 카드는 허용과 사유 있는 거부만 보인다.
- 선택지 질문: 하나 고르기와 여러 개 고르기를 폰에서 답하면 맥에도 같은 답이 뜬다. 맥에서 먼저 답하면 폰 카드가 그 답으로 바뀐다. 대기 중인 질문은 카드 한 장으로 보인다.
- 계획 승인·거부를 폰에서 할 수 있다. 중단 버튼이 맥에 "Interrupted"를 낸다. 맥에서 `/clear`를 하면 거울이 새 기록 파일로 옮겨 간다.
- 맥 입력칸에 쓰던 글이 있으면 폰에 "맥에서 입력 중이라 보내지 못했습니다"가 뜨고, 쓰던 글은 그대로 남는다.
- 맥 cmux 창이 이 세션이 아닌 화면(← 에이전트 목록)을 보이고 있으면, 폰 입력은 그 창이 아니라 tmux로 들어가고 그 창의 입력칸은 비어 있다. 다시 이 세션으로 붙인 창은 깨지지 않는다.
- 거울이 꺼져 있던 동안 폰에서 보낸 말이 맥에 들어가지 않았으면, 거울이 다시 열릴 때 폰에 "맥에 보내지 못했습니다"가 한 번 뜬다.
- 시작한 뒤 worktree로 옮겨 간 세션(일회용 `jarvis-moved`)도 거울 채팅에 지난 기록이 보이고, 폰에서 보낸 말의 답이 이어서 따라온다.
- 맥 입력칸에 쓰던 글이 남은 채 같은 세션을 cmux 창으로 보고 있을 때, 폰 입력은 tmux로 들어가고 cmux 창은 깨지지 않으며 쓰던 글도 그대로다.
- 끝난 거울 채팅에는 "This session is inactive."만 보이고, 터미널 재개 명령(`happy claude --resume …`)은 보이지 않는다. 그 세션은 `claude agents`에 그대로 남아 있어, 다른 곳에서 재개하면 갈라지기 때문이다.
- 거울 채팅 입력칸의 모델 표시는 세션이 실제로 쓰는 모델이다(`--model haiku`로 띄운 세션은 "Haiku 5.5"). 거울이 기록의 assistant 줄에서 모델을 읽어 `metadata.runningModel`로 알린다.
- 폰의 중단 버튼으로 멈추면 맥 기록에 "[Request interrupted by user]"가 남지만, 폰에는 그 말이 사용자 말풍선으로 뜨지 않고 차례만 끝난다.
- 맥 cmux 창을 위로 스크롤해 둔 상태(화면 아래에 "Jump to bottom"이 뜬 상태)에서도 입력칸 위 줄의 세션 이름은 보이므로, 폰 입력은 그 cmux 창으로 들어간다. 창은 맨 아래로 내려가 그 말을 사용자 입력으로 보이고, 답은 맥과 폰 양쪽에 한 번씩 뜬다.
- 권한 창을 거부해 기록에 "[Request interrupted by user for tool use]"가 남아도 폰에는 말풍선이 뜨지 않고 차례만 끝난다. 확인한 창은 폰이 모양을 읽지 못하는 창(EnterWorktree의 "Tool use" 창)이었고, 폰 카드는 "Answer this on your Mac"이어서 맥에서 거부했다. 기록에 남는 줄은 누가 거부했든 같다.
- 폰이 읽지 못한 창의 카드("Unknown")는 맥에서 답해 닫힌 뒤에도 "Answer this on your Mac"으로 남고 Yes/No 버튼이 생기지 않는다. 거울은 그런 요청을 사유 없는 `canceled`로 닫는다.
