# 폰에서 보는 페이지를 읽기 좋게

## 의도

에이전트가 만든 HTML·Markdown 문서를 폰에서 열면 읽기 어렵다. 사용자가 짚은 것(2026-11-12):

- 파일 화면 위에 막대가 셋(「File Viewer」 제목, 세 줄로 접힌 전체 경로, Rendered/Source 탭) 쌓여 화면의 약 30%를 먹는다.
- 이름이 `body.html`처럼만 보여 무엇을 만든 건지 모른다.
- 본문 조각(스타일이 따로 붙는 HTML)은 스타일 없이 화면 끝까지 붙어 보인다. 한국어가 단어 중간에서 끊긴다.

요구: 폰에서 확인하는 HTML 등은 최대한 가독성 좋게 보여야 한다.

## 목표

1. 페이지·Markdown 파일은 제목 줄 하나만 남긴다. 제목은 페이지 제목(없으면 `폴더/파일`), 보기 전환은 제목 줄 오른쪽 아이콘.
2. 본문 조각을 열면, 같은 폴더의 완성본(`폴더이름.html`)이 그 조각을 그대로 담고 있을 때 완성본을 보여 준다. 담고 있지 않으면(조각을 그 뒤에 고쳤으면) 조각을 보여 준다.
3. 조각을 보여 줄 때는 읽기용 기본 스타일(여백·줄 간격·한국어 단어 단위 줄바꿈·넓은 표와 코드 가로 스크롤·그림 폭 맞춤)을 조각 앞에 넣는다. 조각 자신의 스타일이 이긴다. 화면보다 넓은 것(완성본 스타일에 기대는 `min-width` 도식 등)은 그것을 담은 상자 안에서만 가로로 밀리고, 페이지 전체는 화면 폭을 넘지 않는다. 색이 완성본 스타일 변수(`var(--node)`)에서 오는 도식은 검은 덩어리 대신 옅은 면·회색 선으로 그린다.
4. 완전한 페이지인데 모바일 화면 설정(viewport)이 없으면 넣는다. 그 밖에는 손대지 않는다.
5. 채팅 카드의 제목: 완전한 페이지는 `<title>`, 조각은 첫 `<h1>`. 그림(SVG) 안의 `<title>`은 페이지 제목이 아니다. 카드 부제에 폴더 이름을 붙인다.

## 하지 않을 것

- 코드 파일·변경 비교 화면의 막대 배치 변경.
- 새 번역 문자열 추가(기존 문자열만 쓴다).
- 서버·CLI 변경.

## 판단 기준

- Source 보기와 Memo는 처음 연 파일을 가리킨다. 완성본은 보여 주기만 한다.
- 완성본 판정은 "조각 전체가 완성본 안에 그대로 있다"로 한다. 존재만으로 고르지 않는다.
