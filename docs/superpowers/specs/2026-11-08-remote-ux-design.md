# Happy 원격 사용성 개선 (개인 포크) 설계

## 의도

사용자는 갤럭시 폰에서 Happy로 맥의 Claude Code 세션을 조작한다. Claude Code Remote Control을 써 보니 세 가지가 훨씬 편했다.

- 작업 중에 다른 말을 하면 바로 전달된다. Happy는 하던 일이 끝나야 다음 말을 넘긴다.
- 에이전트가 만든 HTML을 앱 안에서 바로 열고, 거기에 메모를 남길 수 있다.
- 워크플로우·서브에이전트가 지금 무엇을 하는지 보인다.

이 경험을 Happy에서 얻는 것이 목적이다. 단, Happy 세션이 Claude Remote Control이나 클라우드에서 돌면 안 된다. Claude는 항상 이 맥에서 직접 실행된다.

## 목표

1. **작업 중 메시지 즉시 전달.** 에이전트가 일하는 중에 보낸 메시지가 다음 도구 실행 경계에서 바로 반영된다.
2. **작업 패널.** 워크플로우, 서브에이전트, 백그라운드 셸 작업의 진행 상황을 앱에서 실시간으로 본다. 끝난 작업도 세션 기록에 남는다.
3. **HTML 미리보기.** 세션 작업 폴더의 `.html` 파일을 앱 안에서 렌더링해 본다.
4. **HTML 메모.** 미리보기에서 위치를 골라 메모를 남기고, 그 메모가 파일 수정으로 이어진다. 동작 방식은 아래 "열린 질문" 참고.
5. **히스토리 찾기.** 지난 세션을 제목·폴더·내용 일부로 검색한다.
6. **실행 모델 보장과 표시.** Opus·Sonnet을 고르면 항상 그 계열의 최신 모델이 돈다. 세션 화면에 실제 실행 중인 모델이 보인다.

## 하지 않을 것

- iOS 앱 포크. 이번 범위는 안드로이드뿐이다.
- Happy 서버 수정. 공식 중계 서버를 그대로 쓴다. 새 메시지 종류도 기존 암호화 봉투에 실어 서버는 내용을 모른 채 중계한다.
- Happy Desktop·Happy Agent 기능 이식. 아티팩트, 브라우저 터널, 협업 문서는 다루지 않는다.
- 스토어 배포. 포크 앱은 사용자 폰에 직접 설치한다.

## 실패로 보는 것

- Claude가 이 맥 밖에서 실행되거나, 세션 내용이 Happy 중계 서버 외의 곳으로 나가는 것.
- 기존 세션이 끊기거나, 스토어판 Happy 앱이 새 메시지 종류 때문에 오작동하는 것.
- 작업 중 전달이 모델·권한 변경까지 섞어 실행 중인 작업을 망가뜨리는 것.
- 업스트림 변경을 합치기 어려울 만큼 코드를 넓게 고치는 것.

## 제약

- **맥.** adb는 USB로만 쓴다(무선 adb는 쓰지 않는다).
- **빌드 환경.** 안드로이드 SDK가 없다. JDK 21은 PATH에 있지만 `java_home`이 깨져 있다. 안드로이드 빌드는 이 맥에서 로컬로 돌린다.
- **맥 CLI 배포.** 맥에는 npm 전역 패키지 `happy` 1.2.6이 깔려 있다. 포크 CLI는 이 저장소 빌드본으로 교체한다. 되돌리기는 `npm install -g happy`. 교체하면 데몬이 버전 차이를 감지해 재시작하므로, 실행 중 Happy 세션이 끊기는지 확인하고 사용자에게 알린 뒤 교체한다.
- **두 앱 공존.** 포크 앱은 다른 applicationId를 써서 스토어판과 나란히 설치한다. 계정은 기존 폰에서 "Link New Device"로 연결한다.
- **업스트림 추종.** 변경은 작고 분리된 단위로 둔다. 작업 중 전달 수정은 업스트림 PR 후보지만, 공개 PR과 GitHub 포크 생성은 실행 전에 사용자 확인을 받는다.

## 검토한 방법

| 방법 | 내용 | 판단 |
|---|---|---|
| 1. 맥 CLI만 수정 | 스토어 앱 그대로. 작업 중 전달은 해결, 작업 현황은 채팅 글로만 표시 | HTML 보기·메모 불가로 목적의 절반을 못 이룸 |
| **2. CLI + 안드로이드 앱 포크** | 목표 전부 가능. 직접 빌드·설치·업스트림 병합 부담 | **사용자 선택(2026-11-08)** |
| 3. Happy Desktop 설치 | 아티팩트·파일·브라우저 터널을 코드 없이 얻음 | 세션 실행 방식이 바뀐다. 작업 중 전달·HTML 메모는 보장 안 됨 |

2번을 단계로 나눈다. 1단계는 CLI만 바꿔 스토어 앱에서도 바로 체감되게 한다.

## 현재 구조 (확인한 사실)

- **CLI 메시지 흐름.** `packages/happy-cli/src/claude/claudeRemote.ts`는 SDK `result` 이벤트를 받은 뒤에야 `opts.nextMessage()`로 다음 사용자 메시지를 SDK 입력 스트림에 넣는다(약 365행).
- **SDK는 작업 중 입력을 받는다.** 2026-11-08 실측. SDK 0.3.319와 Claude Code 2.1.319에서 20초짜리 Bash 실행 중에 두 번째 사용자 메시지를 입력 스트림에 넣었다. Claude는 도구 결과 직후 그 지시를 반영했고, 결과는 하나만 나왔다.
- **앱은 일반 CLI 세션의 작업 중 전송을 막지 않는다.** 차단은 Rig 세션에만 걸린다(`ChatDock.kt:151`). 턴 종료 사유 `steering` 표시는 에이전트 연결 경로 전용이다. 일반 CLI 세션의 턴 종료는 세션 프로토콜의 `completed`, `failed`, `cancelled`만 쓴다(`happy-wire/src/sessionProtocol.ts`).
- **"모드"의 실제 비교 기준.** `runClaude.ts:522`는 plan 모드 여부, 모델, 대체 모델, 두 시스템 프롬프트, 허용·금지 도구, 노력도로 모드를 비교한다. plan이 아닌 권한 변경은 진행 중인 쿼리에 `setPermissionMode`로 바로 적용된다(`claudeRemoteLauncher.ts`의 `handleModeChange`).
- **세션 프로토콜은 동결 상태다.** `sessionProtocol.ts` 머리말이 새 소비자 추가를 막는다. 스토어판 안드로이드 앱은 모르는 이벤트 종류를 버린다(`SessionEnvelope.parse`가 null 반환). 안드로이드는 Rig 세션용으로 `metadata.activity`에서 서브에이전트·워크플로우 개수를 이미 읽는다.
- **작업 이벤트는 버려진다.** `sessionProtocolMapper.ts:531`이 SDK `system` 메시지를 전부 버린다. SDK는 `task_started`, `task_progress`, `task_updated`, `task_notification`을 보낸다. 여기에는 `task_type`(`local_workflow` 포함), `workflow_name`, `subagent_type`, `parent_task_id`, `summary`, `usage`, `status`, `ambient`가 들어 있다(SDK `sdk.d.ts` 6428~6563행).
- **파일 RPC는 일반 CLI에도 있다.** `registerCommonHandlers.ts`에 `readFile`, `writeFile`(해시 가드), `listDirectory`, `getDirectoryTree`, `ripgrep`이 있다. 앱의 `SessionOps.kt:183-215`가 이를 호출한다.
- **HTML은 소스로만 보인다.** `FileScreen.kt`는 `.md`와 이미지만 렌더링하고, `.html`은 문법 강조만 한다(139행). WebView는 아티팩트·Mermaid·브라우저 터널에서 이미 쓰고 있어 의존성은 있다.
- **모델 선택.** 앱은 맥 CLI 버전이 1.2.6-beta.0 이상일 때만 Opus 5.5를 기본으로 쓰고, 버전이 없거나 형식이 깨졌으면 Opus 5로 낮춘다(`AgentDefaults.kt:104-130`). 2026-11-08 데몬이 1.2.6을 보고한 뒤에도 새 세션 두 개에 앱이 `claude-opus-5`, 노력도 high를 보냈다. 원인은 저장된 사용자 선택이거나 앱이 맥 버전을 못 읽은 것이다. 같은 날 설치된 1.2.6 CLI에 로컬 패치로 별칭 변환을 넣어 우회했다(1단계 최신 모델 정책과 같은 동작).
- **히스토리.** 서버가 세션별 암호화 메시지를 보관하고 목록 페이징을 지원한다. 앱 홈에는 세션 내용 검색이 없다.

## 단계와 정해진 동작

### 1단계: 맥 CLI (스토어 앱에서도 효과)

**작업 중 전달.**
- 턴이 도는 동안에도 메시지 큐를 계속 소비한다.
- 들어온 메시지의 모드가 현재 턴과 같으면 즉시 SDK 입력 스트림에 넣는다. "같은 모드"는 `runClaude.ts:522`의 기존 비교 기준을 그대로 쓴다.
- plan이 아닌 권한 변경은 오늘처럼 진행 중인 쿼리에 바로 적용하고, 메시지도 즉시 넣는다. 권한 요청에 막힌 작업을 풀려고 권한을 바꾸는 경우가 많기 때문이다(설계자 판단).
- 그 밖에 모드가 다르면 지금처럼 `result`까지 보류한다. `/clear`, `/compact` 같은 특수 명령도 보류한다.
- 즉시 넣은 메시지는 `result` 뒤에 다시 넣지 않는다. 메시지는 정확히 한 번만 전달한다.
- 세션 프로토콜과 메타데이터는 건드리지 않는다. 그래서 이 변경만 따로 업스트림 PR로 낼 수 있다.

**최신 모델 정책.**
- 앱이 보낸 고정 ID(`claude-opus-5`, `claude-sonnet-5-5[1m]` 등)를 계열 별칭(`opus`, `sonnet[1m]`)으로 바꿔 Claude Code가 최신 모델로 해석하게 한다.
- 환경변수 `HAPPY_MODEL_POLICY=pinned`이면 끈다. 기본값은 켬이다(사용자 요청).
- 하이쿠와 그 밖의 ID는 건드리지 않는다.

### 2단계: 앱 포크 기반

- 안드로이드 SDK와 JDK를 설치하고, `packages/happy-android`를 디버그 서명으로 빌드한다.
- 기존 dev 빌드 변형(`com.slopus.happy.dev`, "Happy (dev)")을 그대로 쓴다. 이미 스토어판과 공존하고 Firebase 항목이 있어 푸시 알림도 온다(설계자 판단). 새 접미사를 만들면 푸시가 끊긴다.
- USB adb로 S23 Ultra에 설치하고, 기존 폰에서 Link New Device로 계정을 연결한다.

### 3단계: 작업 패널

- **CLI.** `task_*` 이벤트를 새 세션 프로토콜 이벤트 `task`로 매핑해 보낸다. 프로토콜이 동결 상태라 이 확장은 포크 전용으로 두고 업스트림에 내지 않는다(설계자 판단). `ambient`와 `skip_transcript` 작업은 패널에만 보이고 대화에는 넣지 않는다.
- **호환성.** 스토어판 앱은 모르는 이벤트 종류를 버리므로 그대로 보내도 안전하다. 진행 중 작업 개수는 기존 `metadata.activity`에도 채워 앱의 기존 표시를 재활용한다.
- **앱 화면.**
  - 세션 화면 상단에 "작업 N개 진행 중" 표시를 두고, 누르면 패널이 열린다.
  - 패널은 워크플로우, 그 아래 에이전트, 셸 작업을 트리로 보여 준다.
  - 각 행에 상태, 한 줄 요약, 경과 시간, 토큰, 마지막 도구를 보여 준다.
  - 끝난 작업은 대화 흐름에 완료 카드로 남아 히스토리가 된다.

### 4단계: HTML 미리보기와 메모

- **미리보기.** `FileScreen`에 `.html`/`.htm`용 "미리보기" 탭을 추가한다.
  - WebView로 렌더링한다. 같은 폴더의 CSS·이미지·JS 같은 상대 경로 자원은 요청을 가로채 `readFile` RPC로 맥에서 읽어 온다.
  - 외부 네트워크 요청은 그대로 허용한다. CDN 폰트·라이브러리를 쓰는 보고서가 많기 때문이다.
- **파일 열기 진입점.** 채팅에 나온 파일 경로를 누르면 이 화면으로 연다. 업스트림 `docs/plans/experimental-chat-file-links.md`를 활용한다.
- **메모.** 아래 열린 질문의 답에 따라 정한다.

### 5단계: 히스토리 검색과 편의

- **검색.** 세션 목록에서 제목, 폴더, 요약 필드로 검색한다. 폰에 이미 내려받아 둔 세션은 메시지 본문까지 찾는다. 모든 세션 본문을 내려받아 색인하는 전체 검색은 하지 않는다(설계자 판단). 검색은 기기 안에서만 한다. 서버는 내용을 모르기 때문이다.
- **실행 모델 표시.** 세션 헤더와 목록 행에 실제 실행 모델을 보여 준다. 값은 SDK `init` 메시지의 `model`에서 온다.
- **전달 상태 표시.** 작업 중에 보낸 메시지에 "작업 중 전달됨" 또는 "작업 끝나면 전달" 표시를 붙인다. CLI 세션에는 `steering` 턴 종료 사유가 없으므로, 앱이 보낼 때의 작업 상태와 이후 도착한 이벤트로 판단한다.

## 열린 질문 (사용자 결정 필요)

사용자가 2026-11-08 개발 진행을 승인했다. 아래 두 질문은 4단계 전까지 다음 가정으로 진행하고, 사용자가 바꾸면 따른다.

- 메모는 에이전트에게 보내고 에이전트가 파일을 고친다(Remote Control 방식).
- 미리보기는 외부 네트워크를 허용한다(맥 브라우저로 여는 것과 같은 수준).

- **HTML 메모의 동작.** Remote Control처럼 메모를 에이전트에게 보내 에이전트가 고치게 할지 정해야 한다. 다른 하나는 메모를 파일에 직접 써넣는 방식이다. 에이전트에게 보내는 방식이면 메모는 고른 위치(요소나 인용 문장)를 담은 채팅 메시지가 되고, 1단계 작업 중 전달에 기댄다. 파일에 직접 쓰면 `writeFile`과 해시 가드, 메모 표기 형식이 필요하다.
- **HTML 미리보기의 외부 네트워크.** 미리보기는 에이전트가 쓴 HTML의 자바스크립트를 실행한다. 외부 네트워크를 열면 CDN 차트·폰트가 보이지만, 이론상 페이지가 담긴 내용을 다른 곳으로 보낼 수 있다. "세션 내용이 중계 서버 외로 나가면 실패" 조건과 부딪히므로 사용자가 정한다.

## 빌더에게 맡기는 것

- 봉투 스키마의 필드 이름과 `happy-wire` 버전 관리.
- 패널의 시각 디자인. 업스트림 앱의 기존 컴포넌트와 톤을 따른다.
- WebView 보안 설정의 세부. 파일 접근 차단, 자바스크립트 허용 범위.
- 각 단계의 테스트 방식. 업스트림의 기존 테스트 관례를 따른다.
